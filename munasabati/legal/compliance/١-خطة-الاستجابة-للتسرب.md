# خطة الاستجابة لتسرب البيانات (٧٢ ساعة)
> مسودة تشغيلية. تُراجع مع محامٍ ومع متطلبات سدايا (اللائحة التنفيذية لنظام حماية البيانات الشخصية) قبل الاعتماد.

## الأدوار
| الدور | المسؤول | المهام |
|---|---|---|
| قائد الحادثة | صاحب المنشأة | يقرر، يوقّع الإشعارات |
| المسؤول التقني | (يُحدد) | الاحتواء، السجلات، تدوير المفاتيح |
| مسؤول حماية البيانات | (يُحدد، ممكن نفس الشخص) | التقييم، التواصل مع سدايا والمتأثرين |

## الخطوات
| الوقت | الخطوة |
|---|---|
| ٠–٤ ساعات | **الاحتواء:** تدوير مفاتيح Supabase (service/anon) وتوكنات Vercel، إيقاف الحسابات المخترقة، تفعيل وضع الصيانة لو لزم |
| ٤–٢٤ ساعة | **التقييم:** وش البيانات المتأثرة (جوالات، أسماء ضيوف، حجوزات)، عدد الأشخاص، الفترة، السبب. حفظ السجلات (Supabase logs، Vercel logs) |
| قبل ٧٢ ساعة | **إشعار سدايا** عبر منصتها الرسمية للحوادث إذا كان فيه ضرر محتمل على أصحاب البيانات |
| بدون تأخير | **إشعار المتأثرين** إذا كان التسرب قد يسبب لهم ضرراً |
| بعدها | تقرير جذر المشكلة، الإصلاح، تحديث الخطة |

## قالب إشعار الجهة المختصة
- اسم المنشأة، السجل التجاري، بيانات مسؤول التواصل
- وصف الحادثة ووقت اكتشافها ووقت وقوعها التقديري
- فئات البيانات وعدد الأشخاص المتأثرين تقريباً
- الآثار المحتملة
- الإجراءات المتخذة والمخطط لها
